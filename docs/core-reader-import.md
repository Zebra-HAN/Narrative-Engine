# 핵심 체험 DB 등록

체험은 기존 `reader` 카테고리를 재사용한다. NAV 객체(이미지 포함)는 그대로 두고 순서만 유형 → 장르 → 도달점 → 체험 → 가치 연출로 변경했다. 기존 `experience`(경험) 데이터와 나머지 카테고리는 유지했다.

## 원본과 분류

`core-reader-source.md`는 첨부 파일을 바이트 단위로 보존한 원본이다. A~I 섹션 제목과 `번호. **제목** — 설명` 카드 행을 구별했다. 번호가 굵은 글씨 안에 있는 편집용 하위 소제목과 분류 경계·검증 요약은 카드로 등록하지 않는다. 원문에 없는 추가 상세정보를 만들지 않는다.

| 그룹 | 섹션 수 | 카드 수 |
| --- | ---: | ---: |
| 도전 · 경쟁 · 위기 | 7 | 370 |
| 모험 · 발견 · 탐구 | 6 | 329 |
| 수집 · 창조 · 육성 | 6 | 336 |
| 거래 · 관계 · 사회 | 4 | 251 |
| 놀이 · 웃음 · 일상 | 3 | 187 |
| 음식 · 예술 · 감각 | 4 | 258 |
| 변이 · 진화 · 각성 | 8 | 79 |
| 감정 · 심리 · 내면 | 8 | 84 |
| 파괴 · 붕괴 · 소멸 | 5 | 50 |
| 합계 | 51 | 1,944 |

원문에는 B~F 대분류명이 없다. 위 B~F 그룹명은 해당 섹션들을 바탕으로 보완한 표시명이며 원문 인용이 아니다. A·G·H·I는 원문의 명칭을 사용한다. 카드 제목과 설명은 공백을 포함해 원문에서 추출한 내용을 유지한다. 중복 카드 제목과 빈 설명은 없다.

## 기존 데이터 구조

도달점·체험의 각 그룹에 `layoutType: '2'`를 설정했다. 실제 카드 격자는 그룹 설정을 읽는다. 도달점 그룹 ID는 유지하고 체험 그룹 ID는 `reader_a`~`reader_i`로 구분한다. 카드 ID는 기존 `그룹 인덱스 * 1000 + 섹션을 포함한 배열 인덱스` 규칙을 그대로 사용한다. 가장 큰 그룹도 1,000개 미만이므로 충돌하지 않는다.

카드는 `name`·`desc`만 사용한다. 섹션은 `type`·`label`만 사용하며 표시용 번호·개수·설명은 이름에서 제거한다. 삭제한 분류 설명과 편집용 소제목은 원본 문서에 보존한다. 카드·섹션 객체는 각각 한 줄로 작성한다.

## 검증 실행

정적 웹앱으로 별도 빌드 도구는 없다. 로컬 HTTP 서버를 띄운 뒤 다음을 실행한다.

```sh
node --check data/compass.js
node --check sw.js
node tests/compass-data.cjs
node tests/compass-destination.cjs
node tests/compass-reader.cjs
PERF_TEST_URL=http://127.0.0.1:8000 node tests/default-card-inclusion.cjs
```

데이터 검증은 원문과 전체 카드·섹션 배열의 순서 및 배치를 대조하고, 변경 대상 외 데이터 보존을 검사한다. 브라우저 검증은 모바일·데스크톱의 그룹 버튼, 카드 격자, 전체 카드 상세 표시, 추가 상세정보 부재, 선택·잠금·랜덤선택·화면 복귀 및 재방문을 검사한다.
