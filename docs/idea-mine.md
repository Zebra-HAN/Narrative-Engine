# 아이디어 광산

기존 화면 전환(switchScreen/goHome)을 사용하는 독립 작업대입니다. 기존 창작 데이터와 저장 키는 변경하지 않습니다.

## 화면 이동

홈의 아이디어 광산은 메인 메뉴로 연결됩니다. 하단 메뉴의 너비는 광산 화면의 약 70%이며 첫 줄에는 되돌아가기/설명, 이후 저장 창고, 아이디어 채굴하기 순서로 배치합니다. 설명은 기존 안내 팝업을 엽니다. Narrative Builder 최초 홈의 배치는 변경하지 않습니다.

광산 메인, 창작 시작의 최초 카테고리 선택 화면, 스토리 구조 최초 화면은 오른쪽 스와이프로 최초 홈에 복귀합니다. 화면 일반 위치에서 시작하는 오른쪽 동작을 감지하고, 바깥 16px는 Safari의 브라우저 뒤로 가기에 남깁니다. 기존 하위 화면과 같은 최소 거리(52px 또는 화면 너비 14%, 상한 80px)·빠른 플릭 판정을 사용합니다. 드래그 중 기존 이중 화살표 플레이트의 CSS와 에셋을 공유하여 표시하고 종료·취소 시 숨깁니다. 팝업·입력·링크·가로 탐색 영역은 제외하며 짧은 동작·세로/왼쪽 동작·취소는 복귀하지 않습니다. 창작 시작의 하위 화면에서는 기존 주소 경로 스와이프를 유지합니다.

뒤로 가기 연출은 화면별로 구분합니다. 창작 최초 진입(카테고리 미선택), 광산 메인, 스토리 구조 최초 진입, 광산 채굴은 화면을 고정하고 기존 그룹·카드의 이중 화살표 플레이트를 그대로 사용합니다. 같은 CSS/에셋/위치/크기/색상/0.16초 등장 동작을 공유하며, 짧게 등장한 뒤 손가락의 이동 거리를 계속 추적하지 않습니다. 홈 또는 이전 광산 화면을 드래그 뒤편에 표시하지 않습니다.

제련소와 저장 창고만 전체 화면 이동과 이전 화면 드러내기를 사용하며, 이때 화살표는 표시하지 않습니다. 저장 창고는 실제 진입 화면(현재 메뉴에서는 광산 메인), 제련소는 기록된 진입 경로(채굴 결과에서 진입 시 채굴 화면)로 돌아갑니다. 짧거나 취소된 동작은 현재 화면과 상태를 복원합니다. 기존 돌아가기 버튼과 재료 선택 중 검색/스크롤·X 닫기는 유지합니다.

창작 내부의 그룹·서브그룹·카드·상세 탐색은 정상 커밋 `7e0995f`의 기존 스와이프 구현을 그대로 유지합니다. 제련소·저장 창고의 이전 화면 시각적 복사본만 shadow root에 격리해 표시하며, 창작 하위 미리보기 수집/캐시는 사용하지 않습니다.

기능 화면은 동일한 광산 화면 내부에서 전환하여 작업대 상태를 유지합니다. 제련소·저장 창고는 여유 높이에서 읽기 내용을 중앙 영역에, 주요 조작을 중앙 아래쪽에 배치하고 긴 내용은 페이지 내부에서 스크롤합니다.

채굴 방식 버튼은 작업대를 빈 재료 슬롯과 안내 문장으로 전환하며 같은 방식을 다시 눌러도 추첨하지 않습니다. 최초 진입도 빈 상태입니다. 채굴 카운터는 채굴하기로 잠금되지 않은 슬롯을 추첨하거나 개별 슬롯 재추첨이 실행될 때 각각 한 번 증가합니다. 방식 변경·재료 선택·잠금·목록 열기/닫기는 증가시키지 않습니다. 방식 버튼은 가로 스크롤을 유지하며 스크롤바만 숨깁니다.

채굴 화면은 별도 스타일 `css/idea-mine-mining.css`로만 리뉴얼합니다. 하늘색 광산 배경 영역과 상단 어두운 안내판, 중앙 크림색 결과 전시 패널, 금색 저장/파란 복사·제련 버튼, 채굴 방식 카드, 재료 카드, 하단 돌아가기/채굴하기/전구 버튼 순서입니다. 작업대 섹션 제목은 제거했습니다. 재료 카드 수는 방식의 기존 필드 수(2개 또는 3개)를 유지하며 재료와 결과 문장은 중앙 정렬합니다. 하단 전구는 기존 제련하기 핸들러를 그대로 공유하고 빈 결과에서는 비활성화합니다.

일반 채굴 화면은 낮은 높이에서 페이지 전체를 세로 스크롤할 수 있습니다. 채굴 방식의 가로 스크롤 및 재료 선택 상태의 독립 스크롤은 유지합니다. 긴 결과는 패널 높이가 늘어나며 조작 버튼과 겹치지 않습니다. 입력 글자는 Safari 확대 방지를 위해 16px를 유지합니다.

돋보기는 별도 재료 선택 상태로 전환합니다. 결과와 결과 조작 버튼, 채굴 방식, 돌아가기/채굴하기를 숨기고 작업대 위의 전체 가용 높이를 재료 목록에 사용합니다. 페이지 전체는 스크롤되지 않고 재료 그리드만 세로 스크롤됩니다. 하단은 검색·표시 개수 다음에 카테고리/X 닫기 행을 배치하며, 붉은 닫기 버튼은 가로 스크롤되는 카테고리 바깥에 고정됩니다. 목록 닫기·재료 선택·슬롯 재추첨 시 기본 화면을 복원하며 재료 값·잠금·방식은 초기화하지 않습니다.

채굴 결과의 아이디어 제련하기는 현재 문장·방식·재료·호환 정보를 복사해 제련소에 전달합니다. 기존 확장 질문과 질문 다시 뽑기 규칙을 그대로 사용합니다. 제련소에서 돌아오면 작업대의 재료·잠금·문장이 유지됩니다. 메인 메뉴의 제련소 진입 버튼은 제거했으며 채굴 결과에서 접근하는 제련 기능은 유지합니다.

채굴·제련소의 저장은 “이 아이디어를 저장하시겠습니까?”, 저장 기록 삭제는 “정말 삭제하시겠습니까?” 팝업에서 예를 선택한 경우에만 적용합니다. 아니오·바깥 클릭·Escape는 취소하며 팝업 안에서 키보드 초점을 유지합니다. 기존 키와 형식으로 같은 저장 창고에 기록합니다. 저장 창고는 기존 조회·작업대 열기·복사·삭제·TXT 내보내기를 유지합니다. 설명 보기는 메인 페이지 위에서 내용 준비 중 안내 팝업을 표시합니다.

## 교체할 디자인 에셋

`data/idea-mine-appearance.js`는 게임/저장 데이터와 분리된 선택적 이미지 설정입니다. 현재 모두 비워 두어 없는 파일을 요청하지 않습니다. 모드 배경은 하늘색으로, 방식/재료 아이콘은 단순 기하형 표식으로 표시합니다. 랜턴·수정·입체 곡괭이·광산 일러스트는 이번에 만들지 않았습니다. 기존 메뉴 배경/타이틀이나 다른 페이지는 변경하지 않습니다.

| 설정 | 연결 대상 |
| --- | --- |
| `backgrounds` | 모드 ID별 광산 배경 이미지 URL |
| `modeIcons` | 모드 ID별 방식 카드 아이콘 이미지 URL |
| `fieldIcons` | 필드 역할별 재료 카드 아이콘 이미지 URL |
| `resultDecoration` | 결과 패널 주변의 투명 장식 이미지 URL |
| `buttonDecoration` | 채굴 버튼 왼쪽의 투명 장식 이미지 URL |

모드 ID는 `action`, `quality`, `rule`, `relation`, `problem`, `why`입니다. 이미지는 실제로 제공된 URL만 지정합니다. 아이콘은 원본 비율로 축소하고 배경은 중앙 cover로 표시합니다. 버튼 장식은 절대 배치하여 교체해도 채굴하기 글자의 가로 중심이 변하지 않습니다.

## 명사 기본형 및 재료 추가

`window.IdeaMineCatalog.materials` 배열에 객체를 추가합니다. `category` 분류 버튼은 자동 생성됩니다. 명사는 **조사 없는 기본형**으로 한 번만 등록하고 역할과 방식을 배열로 지정합니다.

```js
{
  id: 'custom-noun-0001', // 카탈로그 전체에서 고유하고 안정적인 ID
  name: '유리 고래',     // '유리 고래를'처럼 조사를 붙이지 않음
  kind: '명사',
  category: '바다 생물', // 목록 탐색용 분류
  roles: ['subject', 'object'],
  modes: ['action', 'quality', 'relation'],
  grammar: {}           // 향후 확장용; 현재 조사는 이름의 마지막 한글 받침으로 처리
}
```

- `roles`는 슬롯 역할, `modes`는 사용 가능한 채굴 방식입니다. 두 조건이 모두 맞으면 후보에 포함됩니다.
- `modes`를 생략하면 역할이 맞는 모든 방식에서 사용할 수 있습니다. 빈 배열이면 어느 방식에도 사용되지 않습니다.
- 여러 역할·방식은 각각의 조합으로 적용됩니다. 역할별로 다른 방식 제한을 지정하는 별도 매핑은 없습니다.
- `kind`, `grammar`, `schemaVersion`은 메타데이터이며 복잡한 의미 추론이나 품사 자동 변환은 하지 않습니다.
- 같은 이름의 명사를 주체용·대상용으로 중복 등록하지 않습니다. ID도 재사용하지 않습니다.
- 새로운 분류명은 데이터만으로 추가할 수 있습니다. `전체`는 UI의 특수 필터명이라 재료 분류명으로 사용하지 않습니다.
- 후보 배열은 광산 스크립트 초기화 시 구성하므로 추가 파일은 그 전에 로드해야 합니다.

현재 148개 레코드 = **공용 명사 43개 + 기존 비명사 105개**입니다. 이전 명사 등록 85건은 동일 기본형을 통합했습니다. 모든 명사는 주체·대상 역할을 함께 가지며 자유 조합·특성 변형·관계 뒤집기에서 재사용됩니다. 기존 비명사 재료는 변경하지 않았습니다. `마을`의 분류는 통합 시 `장소`로 정리했습니다.

## 슬롯과 문장용 형태

|방식 ID|화면 슬롯 순서|입력 형태 및 문장 규칙|
|---|---|---|
|action|subject → object → verb|명사 기본형 + 이/가, 명사 기본형 + 을/를, 행동 종결형|
|quality|subject → quality|대상은 명사 기본형, 특성은 `살아 움직이는` 같은 관형형; 결과는 특성 + 대상|
|rule|trigger → effect|조건 연결 표현 + 결과 문장|
|relation|subject → object → relation|주체·대상 모두 명사 기본형, 관계는 관형형; 결과는 대상 + 을/를 + 관계 + 주체|
|problem|problem → solution|문제 + `에서 활동하는` + 해결자/직업 등의 명사구|
|why|outcome → cause|결과 문장 + `왜냐하면` + `…기 때문이다` 형태의 원인|

조사 예: `구름이`, `구름을`, `나무가`, `나무를`, `노을이`, `노을을`. 마지막 문자가 한글이 아니면 `이(가)`·`을(를)` 형태로 표시합니다. 숫자·영문 발음 추론은 하지 않습니다. 직접 입력한 새 명사도 기본형을 사용합니다. 비명사 표현의 활용형은 자동 변환하지 않습니다.

별도 파일을 추가하려면 기본 재료 스크립트 다음, core/workbench 스크립트 앞에 로드하고 아래처럼 추가합니다. 오프라인 사용을 위해 `sw.js`의 SHELL 목록에도 파일을 등록합니다.

```js
window.IdeaMineCatalog.materials.push({
  id: 'extra-noun-0001', name: '유리 고래', kind: '명사',
  category: '바다 생물', roles: ['subject', 'object'],
  modes: ['action', 'quality', 'relation'], grammar: {}
});
```

```html
<script src="data/idea-mine-materials.js"></script>
<script src="data/idea-mine-extra.js"></script>
<script src="js/idea-mine-core.js"></script>
<script src="js/idea-mine.js"></script>
```

## 기존 재료 및 저장 호환

- 통합 명사의 `id`는 처음 등록된 기존 ID를 유지했습니다. 통합된 다른 기존 ID는 `legacyIds` 배열에 보존했습니다. 전체 190개 이전 ID가 모두 남아 있습니다.
- 이전 자유 조합 대상 이름(`구름을` 등)은 통합 명사의 `legacyNames`에 남깁니다. 이는 **이전 저장 기록을 읽기 위한 별칭**이며 일반 후보로 표시하지 않습니다. 새 재료에는 이 두 호환 필드를 넣지 않아도 됩니다.
- localStorage 키 `narrative_idea_mine_saves_v1`을 유지합니다. 기존 기록을 일괄 삭제·변경하지 않습니다.
- 불러온 재료를 변경하기 전에는 저장 당시 문장을 그대로 표시해 빈 입력·영문 등 이전 문법 예외도 보존합니다. 이전 기록의 문장과 보관함 표시는 유지합니다. 불러올 때 알려진 조사 포함 이름만 기본형으로 바꾸고, 조사는 다시 붙입니다.
- 이전 사용자 직접 입력 대상은 임의로 조사나 글자를 제거하지 않습니다. 알려지지 않은 대상 표현은 `legacyObject` 호환 표시로 원문 그대로 조합합니다. 이 방식으로 `노을` 같은 단어가 잘못 잘리는 것도 방지합니다.
- 새 저장 기록은 `version: 2`와 필요한 `legacyObject` 정보를 포함합니다. 이전 기록을 다시 저장해도 호환 정보가 유지됩니다.
- 이전 직접 입력 대상이라도 사용자가 해당 슬롯을 새로 편집·선택·재추첨하면 이후에는 기본형 조사 규칙을 적용합니다.
- 저장한 값은 여전히 이름 문자열이며 재료 ID 기반 참조로 전환하지 않았습니다. 방식 배열 순서도 유지해 기존 숫자 mode 값과 호환됩니다.

## 사용 및 확인

목록 선택·직접 편집은 자동 잠금, 불러온 조합은 전체 잠금입니다. 방식 전환은 새 작업대를 시작합니다. 저장 실패 시 성공 메시지 대신 내보내기를 안내하며, 메모리 보관함은 새로고침 전 내보내야 합니다. TXT 내보내기는 읽기/백업용이며 가져오기는 제공하지 않습니다.

문제·해결과 원인 역산은 실험적인 단순 조합입니다. AI 추론·장문 생성·서버·동기화·독창성 평가는 없습니다.

```sh
node tests/idea-mine-core.cjs
node tests/idea-mine.cjs
node tests/home-return-swipe.cjs
```

core 검증은 이전 병합 커밋 `94c52ff`의 재료와 비교하므로 해당 Git 이력이 필요합니다. 브라우저 검증은 설치된 Playwright Chromium/WebKit을 사용합니다. WebKit이 없으면 건너뛰며, 실제 iPhone Safari·홈 화면 PWA 확인을 대체하지 않습니다.
